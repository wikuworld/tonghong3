Skenario uji — Delivery dari Outstanding

Insert delivery marketing dilakukan di Alur Marketing → Outstanding → Susun kirim (packing). Halaman /admin/delivery untuk pantau draft, cetak SJ, dan mark sent. Packing MRP finish (ERP done + QC OK). Gudang FG OUT tidak membuat SJ.

1. Prasyarat data

  • SO confirmed, stage MKT minimal in_outstanding (langsung setelah Confirm)
  • Packing MRP finish: packing ERP done + QC OK + qty; FG in stock
  • Balance SO > 0

2. Kasus uji

Uji 1 — Empty packing (belum done/QC)
Centang baris Outstanding tanpa packing siap → Susun kirim.
Harap: empty-state: packing belum siap.
Berhasil / Gagal
Uji 2 — Full lot / parsial
Pilih packing → qty default = min(sisa packing, balance). Kurangi qty (parsial) → Buat delivery.
Harap: draft SJ di Delivery; packing_detail_id tersimpan; sisa packing berkurang.
Berhasil / Gagal
Uji 3 — Qty > available ditolak
Isi qty lebih dari sisa packing → submit.
Harap: error BE/FE.
Berhasil / Gagal
Uji 4 — Stage sebelum outstanding ditolak
SO masih draft (belum Confirm) → Susun kirim.
Harap: 400: belum tahap Outstanding.
Berhasil / Gagal
Uji 5 — Delivery page follow-up
Buka Delivery → lihat draft → Mark sent / cetak SJ (role warehouse/admin). Marketing melihat banner: insert lewat Outstanding.
Berhasil / Gagal
